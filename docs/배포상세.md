# GitHub Pages 재설정 상세 가이드

Pages Source가 **"Deploy from a branch"로 잘못 변경되어 사이트가 깨졌을 때**,
다시 정상 상태(GitHub Actions 배포)로 되돌리는 전체 과정을 단계별로 정리한다.

> 요약: **Settings → Pages → Source를 "GitHub Actions"로 변경** → **배포 재실행** → **확인**.
> 평소 배포 절차는 [배포방법.md](배포방법.md) 참고.

## 0. 증상 — 지금 어떤 상태인가?

| 확인 방법 | branch 모드(잘못됨) | Actions 모드(정상) |
|---|---|---|
| 브라우저 화면 | 빈 화면 | 포트폴리오 정상 표시 |
| 개발자 도구(F12) → Console | `…/src/main.tsx 404 (Not Found)` 에러 | 에러 없음 |
| 페이지 소스 보기(Ctrl+U) | `<script src="/src/main.tsx">` | `<script src="/my-profile-site/assets/index-XXXX.js">` |

**왜 깨지는가?** branch 모드는 빌드(`npm run build`)를 거치지 않고 **저장소 파일을 그대로** 서빙한다.
소스 `index.html`은 TypeScript 원본(`/src/main.tsx`)을 참조하므로 브라우저가 실행할 수 없다.

> ⚠️ branch 모드로 바뀐 직후에는 멀쩡해 보일 수 있다. branch 모드의 자동 배포
> ("pages build and deployment" 워크플로)는 **다음 푸시 때** 실행되어 그때 덮어쓴다.
> 화면이 정상이어도 Source 설정이 branch라면 시한폭탄 상태이므로 아래 절차로 되돌려야 한다.

## 1. Pages Source 재설정 (웹 UI)

1. 브라우저에서 저장소 설정 페이지 접속:

   **https://github.com/0625chopin/my-profile-site/settings/pages**

   (또는 저장소 → 상단 **Settings** 탭 → 왼쪽 사이드바 **Pages**)

2. **Build and deployment** 섹션에서 **Source** 드롭다운을 찾는다.

3. 현재 값이 **"Deploy from a branch"** 로 되어 있을 것이다.
   드롭다운을 열고 **"GitHub Actions"** 를 선택한다.

   ```
   Build and deployment
   ┌─ Source ──────────────────────────┐
   │  Deploy from a branch        ▼    │   ← 이 드롭다운 자체를 클릭
   ├───────────────────────────────────┤
   │  ● GitHub Actions                 │   ← 이것을 선택
   │  ○ Deploy from a branch           │
   └───────────────────────────────────┘
   ```

4. 선택 즉시 적용된다(별도 Save 버튼 없음).
   아래에 있던 **Branch 선택 드롭다운(main / docs 폴더 등)이 사라지면** 올바르게 바뀐 것이다.

> 구분 포인트: Source 아래에 "Branch: main, / (root)" 같은 브랜치 선택 UI가 **보이면 branch 모드**,
> "Use a suggested workflow…" 안내가 **보이면 Actions 모드**다.

## 2. 배포 재실행

Source만 바꿔서는 화면이 즉시 복구되지 않을 수 있다. 마지막 배포 결과물이 잘못된 것일 수 있으므로
워크플로를 다시 실행해 빌드 결과물을 올린다. 두 방법 중 하나를 사용한다.

### 방법 A — Actions 탭에서 수동 실행 (권장)

1. **https://github.com/0625chopin/my-profile-site/actions** 접속
2. 왼쪽 워크플로 목록에서 **"Deploy to GitHub Pages"** 클릭
   - ⚠️ **"pages build and deployment"** 라는 워크플로도 보일 수 있는데, 이것은 branch 모드가
     자동 생성한 것이다. 클릭하지 말 것 — 우리가 만든 것은 "Deploy to GitHub Pages"다.
3. 오른쪽 **"Run workflow"** 버튼 클릭 → Branch: **main** 확인 → 초록색 **Run workflow** 클릭
4. 몇 초 후 목록에 새 실행이 나타난다. 노란 점(진행 중) → 초록 체크(성공)까지 1분 내외 대기

### 방법 B — 빈 커밋 푸시 (터미널)

```bash
git commit --allow-empty -m "배포 재실행"
git push
```

## 3. 복구 확인

1. **Actions 탭**에서 "Deploy to GitHub Pages" 실행이 **초록 체크(성공)** 인지 확인
   - `build` 잡과 `deploy` 잡 둘 다 성공해야 한다.
   - `deploy` 잡을 클릭하면 배포된 URL이 표시된다.
2. **https://0625chopin.github.io/my-profile-site/** 접속
   - 이전 화면이 캐시되어 있을 수 있으니 **강력 새로고침(Ctrl+F5)** 또는 시크릿 창으로 확인
3. 페이지 소스 보기(Ctrl+U)에서 빌드 결과물 서빙 확인:

   ```html
   <script type="module" crossorigin src="/my-profile-site/assets/index-XXXX.js"></script>
   ```

   여전히 `<script src="/src/main.tsx">`가 보이면 → 1번(Source 설정)부터 다시 확인

## 4. 실패하는 경우별 대처

| 상황 | 대처 |
|---|---|
| Run workflow 버튼이 안 보임 | 워크플로 목록에서 "Deploy to GitHub Pages"를 선택했는지 확인 (`workflow_dispatch` 트리거는 이 워크플로에만 있음) |
| `build` 잡 실패 | 로그에서 에러 확인 → 로컬에서 `npm run build` 재현 후 수정·푸시 |
| `deploy` 잡에서 "Get Pages site failed" / 404 에러 | Source가 아직 GitHub Actions로 변경되지 않은 것 → 1번 재확인 후 **Re-run jobs** |
| 성공했는데 화면이 그대로 | 브라우저 캐시 → Ctrl+F5, 시크릿 창, 또는 1~2분 후 재확인 |
| 다시 깨짐 (시간이 지난 후) | 누군가 Source를 branch로 되돌렸을 가능성 → Settings → Pages에서 Source 재확인 |

## 5. 재발 방지

- **Settings → Pages는 건드릴 일이 없다.** 배포는 전부 `main` 푸시(자동) 또는 Run workflow(수동)로 이뤄진다.
- Actions 탭에 **"pages build and deployment"** 실행 이력이 새로 생긴다면 Source가 branch 모드로
  바뀌었다는 신호다 — 즉시 이 문서의 1번부터 다시 수행한다.
- Source 설정 화면을 다시 볼 때 "어느 쪽이 맞는지" 헷갈리면: **브랜치를 고르는 화면이 보이면 잘못된 것**이라고 기억하면 된다.
